# Minute Meter

A minimal iOS screen time app. This is a personal project: quality over speed, and there's no deadline. The architecture and the reasons behind it are in [docs/architecture.md](docs/architecture.md).

## Workflow

1. Every change starts as a GitHub issue with a goal, scope, acceptance criteria, and what's out of scope.
2. Branch off `main` as `<issue number>-<short-slug>`, for example `12-slide-to-unlock`.
3. Commit in small, working steps as the work progresses.
4. Push the branch and open a PR whose description starts with `Closes #<issue>`.
5. A Claude code review runs on the PR and checks it against the issue. Unit and UI tests will run on PRs too.
6. The owner merges. Never push to `main` directly.

## Keep the owner in the loop

The owner follows Mitchell Hashimoto's "whiteboard defense": they must be able to explain and defend every shipped system at a high level without knowing each line. Claude writes the code; the owner owns the decisions.

- Never do anything the owner didn't ask for. Every action must come from an instruction they gave. If something else seems needed, suggest it instead of doing it.
- Before building anything non-trivial, propose the approach and wait for agreement.
- In every PR description, and when reporting finished work, explain what was built and why. When they apply, also cover:
  - The data structures and design patterns used, and why they beat the alternatives.
  - Where it fails: failure modes, and what a careless or malicious user could do.
  - Anything that couldn't be verified, such as behavior that only works on a device. The owner checks every change on a device as QA.
- Raise tradeoffs and assumptions explicitly. Don't bury decisions in code.
- Keep `docs/architecture.md` current when a PR changes the design.
- Stay concise: short and plain, but never drop what the owner needs to defend the design.

## Project facts

- The Xcode project is generated by XcodeGen. Edit `project.yml`, then run `xcodegen generate`. Don't change settings in Xcode.
- iOS 17+, iPhone only, portrait, light UI. Swift 5 language mode.
- Screen Time APIs don't work in the Simulator. Anything involving shields, relocking, or the app picker needs a check on a real device.
- Say "limit", never "budget", in code and in the UI.
- Use `Shared/DesignTokens.swift` for every color, font, and size. The font is Chivo. Mockups are in `docs/design/`.
- The repo is public. Never commit the APNs key, server secrets, or any other credential.
